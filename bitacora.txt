--- BOTÓN DE INSCRIPCIÓN: BOOTSTRAP Y TAILWIND ---
- Semana 2 (Bootstrap): El enlace "Inscríbete" se presentó visualmente como botón usando las clases de botón que ofrece Bootstrap, un framework basado en componentes predefinidos.
- Hoy (Tailwind): Se mantuvo el enlace HTML y se construyó su apariencia combinando utilidades directamente en el atributo class: px-6 y py-3 para el espaciado, bg-cyan-300 para el fondo, text-slate-950 para el color del texto, y text-lg y font-semibold para la tipografía.
- Diferencia clave: Bootstrap ofrece componentes con estilos predefinidos que se aplican mediante clases de componente; Tailwind es utility-first y permite componer el estilo con clases pequeñas de propósito específico en el propio marcado.
--- GENERACIÓN DE UTILIDADES CON TAILWIND ---
- Clase encontrada: bg-slate-950. Aparece en output.css porque se usa en la etiqueta <main> de index.html.
- Clase no encontrada: bg-pink-500. No aparece porque no se usa en el HTML.
- Explicación: Tailwind escanea los archivos del proyecto y genera el CSS de las utilidades que detecta en uso; omite las clases que no encuentra.

--- REGLAS DEL KIT DE INTERFAZ ---
- Radios: rounded-xl en cards, botones, alertas y campos; rounded-t-xl en las imágenes de las cards.
- Espaciado: se usa la escala Tailwind 1, 2, 3, 4, 6, 8 y 12; 4 para separaciones habituales, 6 para contenido de card y 8 o 12 para secciones.
- Colores base: slate-950 para el fondo, slate-900 para superficies, blanco para texto principal, slate-300 y slate-400 para texto secundario; cyan-300 y cyan-200 para acciones y foco.
- Colores semánticos: emerald para fácil y éxito, amber para intermedio y advertencia, rose para difícil, sky para información.

--- DISTRIBUCIÓN DE RUTAS Y PASOS ---
- Se eligió CSS Grid para organizar las tres cards de rutas en columnas y los cuatro pasos de "¿Cómo funciona?" en una cuadrícula uniforme.
- Justificación: ambos bloques tienen elementos independientes que deben alinearse en filas y columnas; Grid permite controlar esa distribución en dos dimensiones y adaptar el número de columnas a pantallas pequeñas sin cambiar el orden del contenido.

--- REVISIÓN RESPONSIVA A 360 PX ---
- Encabezado: la fila con logo, navegación y botón no cabe en el ancho móvil porque mantiene todos sus elementos en una sola línea.
- Desbordamiento horizontal: en la prueba local a 360 px, el documento ocupó 561 px (201 px adicionales); los enlaces de navegación y el botón "Inscríbete" se extendieron fuera del viewport y quedaron parcialmente inaccesibles sin desplazamiento horizontal.
- Rutas y pasos: en esta vista se distribuyen en una columna; no se observó desbordamiento horizontal en sus cards.

--- COMPARATIVA BOOTSTRAP VS TAILWIND ---
- Medición: 6 de noviembre de 2026. Se activó la minificación de Tailwind CLI con `--minify` y se midió `src/output.css` con `wc -c`; su tamaño es 23.091 B. El mismo archivo comprimido localmente con gzip mide 4.511 B.
- Como referencia antes de minificar, el CSS generado medía 29.148 B: la minificación redujo el archivo en 6.057 B (20,8 %).
- Bootstrap v2.0 se verificó en https://ronald0226.github.io/rueda-libre/. La página carga Bootstrap 5.3.3 desde jsDelivr. En los recursos cargados (DevTools Network / Resource Timing), `bootstrap.min.css` tiene tamaño codificado: 22.709 B y decodificado: 232.803 B. `bootstrap.bundle.min.js` tiene tamaño codificado: 24.464 B y decodificado: 80.721 B. El valor codificado representa el contenido comprimido transferido; el navegador reportó `transferSize` cero por caché, por eso se usa `encodedBodySize`.
- El gzip local del CSS Tailwind (4.511 B) es 80,1 % menor que los 22.709 B codificados del CSS Bootstrap. Se informa aparte que el sitio Bootstrap también descarga JavaScript; no es una comparación de funcionalidades equivalentes.

| Criterio | Bootstrap (sitio v2.0) | Tailwind (landing actual) |
|---|---|---|
| Curva de aprendizaje | Inicio rápido con clases de componentes conocidas como `btn` y `navbar`; hay que aprender sus convenciones y API de componentes. | Requiere aprender utilidades y variantes responsive/estado; el HTML concentra más decisiones de diseño, aunque las clases propias con `@apply` permiten compartir patrones. |
| Personalización | Personalizable mediante variables y Sass, pero adaptar detalles puede implicar sobrescribir estilos del framework. | Personalización directa desde utilidades y tokens `@theme`; facilita aplicar la paleta y variantes claro/oscuro de Rueda Libre sin crear una hoja de componentes extensa. |
| Tamaño final | En la portada v2.0: CSS Bootstrap, 22.709 B codificados (232.803 B decodificados) + JS bundle, 24.464 B codificados (80.721 B decodificados). Además se solicita Bootstrap Icons por separado. | CSS de la landing minificado: 23.091 B (4.511 B en gzip local). Tailwind no aporta JS de runtime para estas utilidades. El CSS sin comprimir es parecido al CSS Bootstrap comprimido, pero con gzip local resulta menor; la comparación de transferencia es orientativa porque gzip se midió localmente. |
| Casos de uso | Conveniente para páginas que necesitan componer rápido componentes predefinidos y comportamientos JS como el carrusel y el menú colapsable del sitio v2.0. | Conveniente para interfaces a medida, con identidad visual propia y estilos responsive compuestos desde utilidades; también para landings como esta, donde el CSS generado incluye las clases utilizadas. |

- Recomendación para Rueda Libre: mantener Tailwind en la landing personalizada. Sus tokens de marca, los tres botones reutilizables con `@apply` y el CSS final comprimible favorecen consistencia y bajo peso. Para una versión que conserve carrusel y navegación interactiva de Bootstrap, contabilizar aparte o sustituir explícitamente esos comportamientos JavaScript; Tailwind por sí solo no los proporciona.

--- FORMULARIO DE INSCRIPCIÓN ---
- Se añadieron campos semánticos y etiquetas asociadas para nombre completo, correo, celular, ruta, día de salida, acompañantes, experiencia, bicicleta propia y aceptación de condiciones.
- Se usa validación nativa del navegador: todos los campos son requeridos; el nombre tiene mínimo 3 caracteres; el correo usa `type=email`; el celular debe tener exactamente 10 dígitos y comenzar por 3; los acompañantes están limitados a enteros de 0 a 3; rutas y días se seleccionan de las opciones solicitadas.
- Bloqueo de entrega: el sitio es estático y no hay un destino de recepción configurado. El botón de envío permanece deshabilitado y se muestra el motivo; no se envían datos personales a servicios externos ni se simula una confirmación.

--- PRUEBA DE TECLADO Y VALIDACIÓN DEL FORMULARIO ---
- Fecha: 6 de noviembre de 2026.
- Tiempo medido en navegador: 107 ms para la secuencia automatizada de teclado desde el inicio del recorrido hasta la validación final; no incluye la carga de la página.
- Recorrido: se usaron Tab y Mayús+Tab para avanzar y retroceder, flechas para elegir opciones y barra espaciadora para aceptar las condiciones; no se usó el mouse.
- Formulario vacío: rechazado; se identificaron como inválidos nombre, correo, celular, ruta, día, experiencia, bicicleta propia y aceptación de condiciones. Acompañantes inicia en 0.

- Datos completos: pasó la validación del navegador con los campos requeridos completos, celular de 10 dígitos iniciado en 3 y 3 acompañantes.
- El envío no se ejecutó: el botón sigue deshabilitado porque falta configurar el destino de recepción.
